# Requirements Document

## Introduction

Add AgentCore short-term memory to the Bush Ranger AI agent so that conversations maintain context across turns within a single session. Currently, each invocation of the Strands Agent creates a fresh `Agent()` instance with no memory of prior turns, meaning the agent cannot reference earlier messages in a conversation. This feature integrates the AgentCore Memory managed service (short-term mode only) via the Strands SDK's `AgentCoreMemorySessionManager`, enabling turn-by-turn conversational context.

## Glossary

- **Agent_Handler**: The Strands Agent entry point (`services/agent/handler.py`) that runs on AgentCore Runtime and processes user messages.
- **API_Lambda**: The Lambda function (`services/api/handler.py`) that proxies requests from API Gateway to the AgentCore Runtime.
- **Chat_Frontend**: The React chat UI (`frontend/src/chat/ChatPage.tsx`) that sends user messages and displays agent responses.
- **Auth_Provider**: The Cognito authentication module (`frontend/src/auth/AuthProvider.tsx`) that manages user sessions and access tokens.
- **CDK_Stack**: The CDK infrastructure stack (`infra/stacks/bush_ranger_stack.py`) that provisions all AWS resources.
- **Memory_Resource**: An AgentCore Memory resource created once during infrastructure deployment and referenced by its `memory_id` at runtime.
- **Session_Manager**: An `AgentCoreMemorySessionManager` instance from the Strands SDK that manages short-term conversational memory for the agent.
- **session_id**: A unique identifier for a conversation session, generated by the Chat_Frontend and sent with each message to maintain turn-by-turn context.
- **actor_id**: The authenticated Cognito user's unique identifier (`sub` claim from the JWT), used to associate memory with a specific user.
- **memory_id**: The identifier of the pre-created AgentCore Memory_Resource, passed to the Session_Manager at runtime.

## Requirements

### Requirement 1: Frontend Session Tracking

**User Story:** As a park ranger, I want my chat session to be tracked so that the agent remembers what I said earlier in the conversation.

#### Acceptance Criteria

1. WHEN the Chat_Frontend loads, THE Chat_Frontend SHALL generate a unique session_id using `crypto.randomUUID()` and store it in component state.
2. WHILE a session_id exists in component state, THE Chat_Frontend SHALL include the session_id in every request body sent to the `/invoke` endpoint.
3. WHEN the user signs out, THE Chat_Frontend SHALL discard the current session_id.
4. WHEN the user signs in, THE Chat_Frontend SHALL generate a new session_id.

### Requirement 2: Frontend Actor Identity

**User Story:** As a park ranger, I want my identity to be associated with my conversation so that memory is scoped to my account.

#### Acceptance Criteria

1. THE Chat_Frontend SHALL extract the `sub` claim from the Cognito access token and include it as the `actorId` field in every request body sent to the `/invoke` endpoint.
2. IF the access token is unavailable or cannot be decoded, THEN THE Chat_Frontend SHALL omit the `actorId` field from the request body.

### Requirement 3: API Lambda Passthrough

**User Story:** As a system integrator, I want the API Lambda to forward session and identity information to the agent so that memory can be initialized correctly.

#### Acceptance Criteria

1. WHEN the API_Lambda receives a request containing a `sessionId` field, THE API_Lambda SHALL include the `sessionId` value in the agent payload forwarded to the AgentCore Runtime.
2. WHEN the API_Lambda receives a request containing an `actorId` field, THE API_Lambda SHALL include the `actorId` value in the agent payload forwarded to the AgentCore Runtime.
3. IF the request does not contain a `sessionId` field, THEN THE API_Lambda SHALL generate a fallback session_id using `uuid.uuid4()` and include it in the agent payload.

### Requirement 4: Agent Memory Integration

**User Story:** As a park ranger, I want the agent to remember prior turns in my conversation so that I do not have to repeat context.

#### Acceptance Criteria

1. WHEN the Agent_Handler receives a payload containing `session_id`, `actor_id`, and the configured `memory_id`, THE Agent_Handler SHALL create an `AgentCoreMemoryConfig` with those three values.
2. WHEN a valid `AgentCoreMemoryConfig` is created, THE Agent_Handler SHALL instantiate an `AgentCoreMemorySessionManager` and pass it as the `session_manager` parameter to the `Agent()` constructor.
3. WHILE the Session_Manager is active, THE Agent_Handler SHALL rely on the Session_Manager to load prior turns and append new turns for the current session.
4. IF the `memory_id` environment variable is not configured, THEN THE Agent_Handler SHALL create the Agent without a session_manager and log a warning.
5. IF the Session_Manager initialization fails, THEN THE Agent_Handler SHALL fall back to creating the Agent without a session_manager and log the error.

### Requirement 5: Infrastructure — Memory Resource

**User Story:** As a DevOps engineer, I want the AgentCore Memory resource to be provisioned automatically so that the agent can use short-term memory without manual setup.

#### Acceptance Criteria

1. THE CDK_Stack SHALL create an AgentCore Memory_Resource during deployment.
2. THE CDK_Stack SHALL pass the Memory_Resource identifier as the `MEMORY_ID` environment variable to the Agent Runtime.
3. THE CDK_Stack SHALL output the Memory_Resource identifier as a CloudFormation stack output.

### Requirement 6: Infrastructure — IAM Permissions

**User Story:** As a DevOps engineer, I want the agent's IAM role to have the permissions required to use AgentCore Memory so that memory operations succeed at runtime.

#### Acceptance Criteria

1. THE CDK_Stack SHALL grant the Agent Runtime IAM role permission to perform `bedrock-agentcore:InvokeMemory` actions on the Memory_Resource.
2. THE CDK_Stack SHALL grant the Agent Runtime IAM role permission to perform `bedrock-agentcore:RetrieveMemory` actions on the Memory_Resource.
3. THE CDK_Stack SHALL scope memory IAM permissions to the specific Memory_Resource ARN.

### Requirement 7: Dependency Management

**User Story:** As a developer, I want the required AgentCore memory packages to be declared as dependencies so that the agent handler can import them.

#### Acceptance Criteria

1. THE Agent_Handler's dependency manifest SHALL include the `bedrock-agentcore` package with memory extras.
2. THE Agent_Handler's dependency manifest SHALL include the `bedrock-agentcore[strands]` integration package for the Strands SDK memory session manager.

### Requirement 8: Session Continuity Across Turns

**User Story:** As a park ranger, I want to ask follow-up questions without restating context so that my workflow is efficient.

#### Acceptance Criteria

1. WHEN a user sends a second message with the same session_id, THE Agent_Handler SHALL have access to the conversation history from the first message via the Session_Manager.
2. WHEN a user sends a message with a new session_id, THE Agent_Handler SHALL start with an empty conversation history.
3. FOR ALL sequences of messages within a single session, sending messages then retrieving memory then sending more messages SHALL produce a conversation history that contains all prior turns in order (round-trip property).
